# 日本株AI仮説研究

J-Quantsで取得済みの日本株データから、AIが最大10件の仮説を立て、各仮説が成立した後の5・10・20営業日の騰落を調べます。1回のコマンドで仮説生成、検証、AIの解釈、HTMLレポート出力まで進みます。

## Windowsで起動する

Python 3.12とuvを使用します。自宅・職場の各PCで初回だけ実行してください。

```powershell
git clone https://github.com/seikoubon/japan-swing-ai-research.git
cd japan-swing-ai-research
uv sync
uv run python -m unittest -v
```

通常は既存データ基盤で同期済みの `data` を指定します。場所が異なる場合はパスを変更してください。OpenAI APIキーは各PCの環境変数 `OPENAI_API_KEY` に設定します。現在のPowerShellだけに設定する場合は、非表示入力を使えます。

```powershell
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'OpenAI API key' -AsSecureString)).Password
uv run python research.py --clean ..\japan-swing-trading\data
```

画面に表示された `reports\実行ID\report.html` をブラウザで開きます。各仮説を展開すると、根拠、条件、件数、中央値、年別・市場環境別成績を確認できます。同じフォルダーに仕様と結果のJSONがあります。コード更新は両PCで `git pull --ff-only`、次に `uv sync` を実行します。

### 初回と同じ入力で再現する

初回の非公開HTML末尾の「仮説仕様を保存」で `hypotheses.json` を保存します。次のコマンドはAPIを呼びません。

```powershell
uv run python research.py --cache ..\japan-swing-gui\reports\local-cache-stage6 --spec .\hypotheses.json
```

この入力形式は2026-11-13までの既存Stage 6スナップショット専用です。`bars.bin` と `meta.json` が必要です。価格ファイル、日付・コード配列のハッシュを検査します。日次の新しいデータで調べる場合は `--clean` を使います。ローカルデータの同期は従来のデータ基盤が担当します。

### 前回の知見を次に渡す

同じPCでは直近2回の検証要約とAI解釈を自動で参照します。他方のPCや初回研究の結果は、レポートの「研究結果を保存」で取り出し、次のように渡せます。読み込むのは仮説と検証期間の要約です。

```powershell
uv run python research.py --clean ..\japan-swing-trading\data --previous .\result.json
```

## 研究方法

- 入力は月別のClean Parquet（prices、master、calendar）または既存の価格キャッシュ。毎回入力の版を記録。Raw、R2、EDINETへの接続や定期ジョブはありません。
- 当日の市場・商品区分・コードで東証普通株を近似。旧市場を含み、後に上場廃止となった銘柄もその時点の在籍に従って含めます。銘柄コードを現存一覧で絞り込みません。
- 特徴量は5/20/60日騰落、25日移動平均乖離、出来高倍率、当日の陽線・陰線の幅、市場の騰落銘柄割合、20日相対リターン。AIは学習期間の分布を読んで経済的な理由、主たる保有期間、最大4条件のANDを生成。許可リスト外の特徴・演算子や重複は実行前に除外します。財務・信用残の利用可能日検証は次段階です。
- 株式分割は当日までの係数で前向きに換算。非適格・無売買の日、価格欠損、権利イベントの前後をまたぐ履歴を結合しません。出口消失をゼロ収益扱いせず、成立件数と観測件数を併記します。欠測銘柄に偏りがあれば残存バイアスがあります。過去に配信された訂正前の版は再現できません。
- シグナル日の翌営業日始値から、さらに5/10/20営業日後の始値までを測定。市場基準は当日の対象群で同じ期間の始値リターンが観測できた全銘柄の単純平均。地合いは当日の対象群の平均20日リターンがゼロ以上かで分類します。
- 学習は2021年末まで、検証は2022〜2023年、最終期間は2024年以降で固定。出口が期間を越えるシグナルは期間ごと・保有期間ごとに除外。5/10/20日のうち判定に使う主期間は事前固定します。
- 主判定は成立銘柄を日ごとに平均し、同日市場平均との差から往復30bpを引いた後、成立日を均等に平均。手数料とスリッページを合わせた近似です。HAC標準誤差（Bartlett、ラグ2×保有日数）と片側正規近似、当該回の提案数によるBonferroni補正を使用します。繰り返し検証した期間には探索バイアスが残ります。
- 候補は補正p値<0.05、費用後超過>0、20銘柄・100成立日・200観測以上、観測率95%以上、上位5銘柄の件数比率25%以下。失敗した仮説も保存します。初期段階はイベント研究まで。個々の理論リターンから500万円・10銘柄の資金曲線を推定しません。

通常起動では最終期間を温存します。開封するときだけ、2台のうち1台を最終評価専用に選び、その端末で `$env:SWING_FINAL_PC='1'` を設定して `--final` を付けます。検証を通過した最上位1件だけを採用し、該当期間の開封を台帳に1回記録します。もう一方のPCではこの設定をしないでください。

## 計算エンジン

DuckDBで月別Parquetの結合、銘柄別の連続区間・窓計算と仮説の集計を行います。価格キャッシュはNumPyの読み取り専用メモリマップで64日ずつ読みます。入力は変更せず、実行用DBはOSの一時フォルダーに置いて終了時に削除します。

同一の100万行の実データParquetに同じ3条件を適用し、件数と3期間の平均を比較。別プロセス各1回、ライブラリ読み込み込みでDuckDBは0.113秒・141 MiB、pandas＋PyArrowは0.323秒・303 MiB。結果は丸め誤差内で一致しました。これは当該の抽出・集計に対する測定です。

既存VectorBT研究室は単一銘柄の指標・売買を実装。既存の独自エンジンには複数銘柄の注文予約、流動性制約、部分売却、企業イベント処理があります。今回は成立後リターンの統計処理を選定対象とし、この2つの売買エンジンの全市場速度順位は測定していません。通過候補が出た段階で既存エンジンへの入力を追加します。

## APIと予算

通常は生成と評価の最大2回。OpenAI Responses APIに渡すのは特徴分布・仮説・集計値です。標準モデルは `gpt-4.1-mini-2025-04-14`。`--model gpt-4.1-nano-2025-04-14` にも変更できます。料金表は `api.py` の許可リストで管理します。[miniの公式情報](https://developers.openai.com/api/docs/models/gpt-4.1-mini)・[nanoの公式情報](https://developers.openai.com/api/docs/models/gpt-4.1-nano)

1実行2米ドル、自宅・職場は各月10米ドルずつ（合計20米ドル、JST月）。各PCの同一ユーザーの台帳を全チェックアウトで共有します。送信前に最大額を予約し、応答のトークン数で精算。通信断などで使用量が不明なら予約を保持。キャッシュ入力も通常入力単価で保守的に見積もります。台帳は各PCのユーザーフォルダー配下の `.japan-swing-ai-research/state.sqlite3` にあるため、削除・複製による予算や開封履歴のリセットは避けてください。他アプリの利用額、APIクレジット残高・有効期限は取得しません。

## 動作確認の範囲

Python 3.12のLinux環境で実データの手動CLI実行を確認。全期間の初回研究は既存価格キャッシュを使用。Clean Parquet経路はJ-Quantsの短期実データでも読込み確認。合成データで分割、翌日始値、欠損・再在籍、期間境界、複数銘柄、予算制御、最終期間の保護をテストしています。API通信は模擬応答で検査。初回はCodexが生成した仕様を再生し、実APIでの生成・解釈とWindows実機の動作は未確認です。
